# Trident Research Core Foundation

## 本阶段目标

在不改变现有 Streamlit 页面、研究流程和报告能力的前提下，把研究服务从页面层解耦。页面现在只是一个交付适配器；同一套 Research Core 后续可以被 FastAPI、后台任务、企业工作流插件或其他前端调用。

## 当前分层

1. `src/ui`：现有 Streamlit 交互与页面状态，只负责展示和用户操作。
2. `src/core`：运行上下文、服务容器、扩展注册表、算法治理规则。
3. `src/services`：研究规划、证据、行业分析、趋势、报告、评分和行动计划。
4. `src/providers`：模型和搜索供应商适配器。
5. `src/models` 与 `src/state`：结构化研究产物和当前项目状态。

## 为未来场景预留的扩展口

- `ScenarioPack`：PE/VC、企业增长、其他决策场景的输入、流程和输出规则。
- `IndustryPack`：行业术语、指标、基准和专家知识。
- `AlgorithmStrategy`：市场预测、相似公司、评分、风险模型等可替换算法。
- `ArtifactEvaluator`：对研究产物进行事实性、覆盖度、可解释性和业务价值评估。
- `EventSink`：沉淀隐私安全的运行事件，形成可审计的评估和学习数据。
- `ResearchRunContext`：锁定每次运行使用的工作流、场景包、行业包和版本，保证可复现与可追责。

## “自我进化”的安全实现方式

Trident 不允许模型直接修改线上 Prompt、算法或工作流。自我进化采用受控闭环：

1. **观察**：记录结构化输入、输出、人工修改、证据采用和行动结果。
2. **评估**：按场景和行业运行离线评测，识别失败模式和改进机会。
3. **提出候选**：算法或模型生成新的 Prompt、检索策略、评分权重或模型版本候选。
4. **离线验证**：候选必须通过历史回放、回归测试、红队测试和质量阈值。
5. **人工批准**：研究负责人或算法负责人审查解释、风险和适用边界。
6. **灰度运行**：少量项目进入 canary，对照当前生产版本。
7. **晋升或回滚**：效果稳定才晋升；异常时按版本立即回滚。

`EvolutionPolicy` 已建立最低评测分、最低案例数和人工批准闸门。后续算法团队可在不修改 UI 或核心业务模型的情况下增加评估器和候选策略。

## 下一阶段

下一阶段在该容器外增加 FastAPI 交付层、任务队列与持久化仓储接口。届时 Streamlit 与新前端可以并行调用同一核心，避免一次性重写导致功能丢失。
