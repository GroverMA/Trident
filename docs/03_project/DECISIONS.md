# 关键技术与产品决策

本文件采用轻量 ADR（Architecture Decision Record）形式，记录 Trident 已确认的关键决策。任何改变系统边界、数据责任、研究方法或部署策略的修改，都应先更新本文件。

## ADR-001：采用 Python 研究内核、FastAPI 服务层与 Next.js 工作台

- **日期**：2026-08-17
- **状态**：已接受
- **背景**：原型以 Streamlit 快速验证了行业研究流程，但企业级产品需要稳定 API、多用户界面、异步任务和外部系统集成能力。
- **决策**：保留 Python 研究和文档处理能力；以 FastAPI 暴露业务 API；以 Next.js 构建正式 Web 工作台。Streamlit 仅保留为原始演示和回归参照，不作为新产品主界面。
- **原因**：Python 适合 AI、数据和研究编排；FastAPI 便于形成可测试服务边界；Next.js 更适合复杂交互、权限和企业门户集成。
- **备选方案**：继续以 Streamlit 承载全部功能；迁移至低代码平台；将前后端全部改写为 TypeScript。
- **后果**：需要维护清晰的 API 合同和前后端状态同步，但可获得更强的可扩展性与部署选择。

## ADR-002：构建式研究与审阅式研究是工作路径，不是用户身份

- **日期**：2026-08-17
- **状态**：已接受
- **背景**：两类用户可能在同一项目中切换研究进入方式，固定身份会造成权限与流程概念混淆。
- **决策**：两条路径共享同一项目、证据库、分析工件和报告版本；切换只改变流程呈现顺序，不清空内容。
- **原因**：符合真实研究协作方式，也避免形成两套难以同步的数据模型。
- **备选方案**：按 Consultant 与 Reviewer 建立独立产品和数据库。
- **后果**：页面状态必须与领域状态分离；路径切换需要回归测试。

## ADR-003：场景、行业知识与算法能力均通过可插拔合同扩展

- **日期**：2026-08-17
- **状态**：已接受
- **背景**：Trident 将支持通用行研、企业增长、PE/VC 等场景，并持续接入行业知识包和专业算法。
- **决策**：使用 Scenario、Industry、Skill、Algorithm 等稳定合同注册能力，研究主流程只依赖合同，不直接依赖某个场景实现。
- **原因**：避免复制整套 Agent；允许专业团队独立迭代算法、研究 Skill 和场景模块。
- **备选方案**：为每个场景复制一个应用；在主流程中大量使用条件分支。
- **后果**：需要版本化注册表、兼容性测试和场景级评估集。

## ADR-004：PostgreSQL 是正式数据底座，SQLite 仅用于明确标记的 Demo

- **日期**：2026-08-17
- **状态**：已接受
- **背景**：融资演示需要低成本和快速部署，正式客户版本则需要并发、备份、租户隔离和审计。
- **决策**：正式环境使用 PostgreSQL；SQLite 只允许在显式 Demo 配置下使用。生产配置缺少数据库连接时应明确报错，不静默降级。
- **原因**：防止测试数据和正式数据责任边界混淆，同时保留低成本演示能力。
- **备选方案**：所有环境长期使用 SQLite；完全依赖平台专有数据库 API。
- **后果**：必须维护迁移脚本、备份策略和 Demo 至 PostgreSQL 的迁移路径。

## ADR-005：长时间研究任务从 Web 请求中分离

- **日期**：2026-08-17
- **状态**：已接受
- **背景**：搜索、抓取、分析和报告生成可能持续数分钟，直接占用请求会受平台超时和网页中断影响。
- **决策**：研究运行以 Job 表示，由 Worker 异步执行；Web 端订阅状态并支持失败重试、断点恢复和幂等执行。早期可用单 Worker，规模化后迁移至 Celery 或 Temporal 类调度。
- **原因**：保证长任务可靠性，并支持多人、多项目并行。
- **备选方案**：所有研究步骤都在同步 HTTP 请求中执行。
- **后果**：需要任务状态机、事件记录、可观测性和取消语义。

## ADR-006：Company Scorecard 必须同时呈现三条评分线

- **日期**：2026-08-17
- **状态**：已接受
- **背景**：单一公司得分无法说明企业在市场中的位置，也不能直接推导战略差距。
- **决策**：每个动态评估维度必须同时包含公司当前得分、同类市场玩家平均基准和实现战略目标所需分数；Action Plan 由两类差距及企业约束共同推导。
- **原因**：把行业趋势、企业现状和战略目标连接成可行动判断。
- **备选方案**：只给公司总分；使用固定六维、固定 90 分市场基准。
- **后果**：必须保存指标定义、计算依据、置信度和版本，雷达图只是呈现层，不替代评分证据。

## ADR-007：海外与中国大陆采用同一产品版本和研究流程

- **日期**：2026-08-18
- **状态**：已接受
- **背景**：Vercel 解决海外访问，腾讯云 CloudBase 解决中国大陆访问；如果按区域复制
  研究流程或功能，迁移与后续开发会产生不可控漂移。
- **决策**：两个区域从同一仓库、同一发布版本构建，共享研究内核、Web 功能、API 与
  数据契约、Skill/Prompt、报告规则和测试集。差异只允许存在于部署拓扑、区域资源、
  Secret、Provider 配置、数据驻留和合规策略，并通过配置或适配器实现。
- **原因**：保证研究质量、用户体验和修复同步，避免维护两套产品并降低双区域发布成本。
- **备选方案**：维护大陆版与海外版独立分支；按区域裁剪研究流程；先长期单区上线后手工同步。
- **后果**：每次迁移、新功能和修复必须进行双区域影响评估与发布验收；任一区域未完成时
  只能标记部分部署。基础设施差异需要稳定适配器和配置验证，不得渗入领域研究逻辑。
