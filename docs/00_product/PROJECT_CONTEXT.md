# Project Context

## Background

Trident 是一个面向行业研究与企业战略决策的 AI Agent。它的起点不是“自动写一篇报告”，而是把专业研究能力拆成可追踪、可审核、可复用的工作流：定义问题、锁定市场边界、收集证据、形成判断、预测趋势、映射企业差距并生成行动方案。

品牌主张：**Dive Deep into Industries. Surface with Direction.**

## Problem

通用生成式 AI 能够整理信息，却经常缺少以下能力：

- 无法稳定界定研究问题与市场口径。
- 事实、观点、推断和预测混在一起，难以核验和追责。
- 只复述既有报告，缺少竞争逻辑、反证和未来情景判断。
- 行业分析与企业内部数据脱节，难以转化为“做什么、谁来做、何时开始”。
- 长任务容易受网页超时或单次模型调用失败影响。
- 项目、证据、判断与行动缺乏长期记忆，不能持续迭代。

## Vision

把 Trident 建成可配置的“研究与决策操作系统”：同一底座支持通用行业研究、企业增长策略、PE/VC 投资研究及未来更多场景模块；研究方法、证据、判断和责任边界可见，结论可直接进入业务决策。

## Goals

### 当前目标

- 提供构建式研究与审阅式研究两条可切换路径。
- 支持通用行业报告和企业战略报告。
- 以统一 SOP 生成行业定义、产业链、市场规模、竞争格局、驱动因素与未来展望。
- 接入模型与网页搜索，保留人工确认和可追溯证据。
- 输出网页、Word 与 PDF 报告。
- 通过 Next.js + FastAPI 提供可扩展 Web 底座，同时保留 Streamlit 兼容版本。

### 中期目标

- 多用户、多租户、权限、审计、异步长任务与长期记忆。
- 持续感知新闻、政策、竞争者、客户与企业内部信号。
- 上线 PE/VC 与中小企业增长决策场景包。
- 根据执行反馈动态调整 Action Plan。

### 长期目标

- 支持企业私有云/VPC 部署和 SAP、CRM、数据仓库连接。
- 建立行业、企业、项目、判断与行动的时间化知识图谱。
- 允许专业算法团队插入新的评分、预测、仿真和评估策略。

## Users

- 咨询顾问、行业研究员和企业市场研究人员。
- 报告审阅者、研究负责人和管理层。
- 缺少完整市场与战略团队的中小企业老板及经营团队。
- PE/VC 投资经理、研究员和投资委员会成员。
- 企业 IT、数据与安全团队。

## Use Cases

1. 研究全球及中国某行业的市场现状、竞争格局与未来趋势。
2. 审阅 AI 初稿，追溯证据与分析逻辑，并按模块迭代报告。
3. 上传企业内部经营资料，形成企业定位、Company Scorecard 和定制 Action Plan。
4. 持续监测政策、竞争者、客户和行业信号，并触发决策更新。
5. 对投资标的进行主动访谈、行业验证、标的画像、情景模拟和投委会材料准备。

## Scope

### 当前范围

- 项目创建、恢复、分类和研究状态管理。
- 两种研究方式，共享同一项目数据与报告版本。
- 研究简报、市场口径、研究计划、网页证据、行业分析、未来趋势。
- 企业资料接入、评分、行动计划和正式报告。
- HKGAI 兼容模型与搜索服务；接口可替换。
- FastAPI、Next.js、SQL 持久化、CloudBase 中国 Demo 与海外部署基础。

### 规划范围

- 多租户、组织权限、异步任务编排、持续感知、长期记忆、场景包注册表。
- PE/VC、增长策略及其他垂直场景。
- 企业 API、SSO、私有部署、知识图谱与高级算法插件。

## Out of Scope

- 当前版本不替代律师、审计师、医生或受监管专业人士的最终责任。
- 当前版本不承诺自动获得付费数据库或未经授权的内部数据。
- 当前版本不以自建基础模型或购买 GPU 集群为前提。
- 当前版本不把模型隐含推理过程作为对外产品输出。
- 未完成多租户隔离前，不作为正式生产 SaaS 承载真实客户机密。

## Terminology

| 术语 | 含义 |
|---|---|
| Research Build First | 构建式研究，从问题、证据和分析逐步形成报告。 |
| Report Review First | 审阅式研究，先生成完整初稿，再追溯与修订。 |
| Enterprise Sensing | 企业一手资料、访谈、经营信号及外部持续感知入口。 |
| Evidence | 可追溯的事实、数据、原文摘要或有明确来源的观点。 |
| Finding | 由一个或多个证据综合形成的研究判断。 |
| Company Scorecard | 公司能力、市场平均基准和战略目标要求之间的量化比较。 |
| Action Plan | 针对评分差距和战略目标生成的短期、长期行动。 |
| Industry Pack | 特定行业知识、分类、指标、基准与研究规则的可插拔包。 |
| Scenario Pack | PE/VC、增长策略等业务场景的工作流和输出契约。 |

## Constraints

- 两种研究方式必须共享项目、证据和报告版本，切换不得丢失数据。
- 正式报告不得出现内部 Evidence/Finding 编码或工程错误信息。
- 企业机密不得进入公开 Demo、日志、仓库或前端代码。
- 中国大陆与海外访问需要共用一套代码，通过部署配置区分。
- Vercel 海外版与腾讯云大陆版必须同时拥有相同研究流程、功能、领域/API/Skill 版本和
  报告标准；所有迁移、新功能与修复同步进入两个部署目标并接受双区域验收。
- 当前中国 Demo 可显式使用 SQLite 保障可运行；生产客户路径必须迁移到 PostgreSQL。
- 搜索与模型提供商可替换，业务逻辑不得绑定单一供应商。

## Dependencies

- 模型 API：当前采用 OpenAI 兼容接口。
- 搜索工具：当前采用 REST/MCP 搜索与抓取服务。
- Web：Next.js；后端：Python + FastAPI。
- 持久化：SQLAlchemy，支持 SQLite、PostgreSQL 与 MySQL 方言。
- 报告：DOCX/PDF 导出依赖相应文档与字体运行时。
- 部署：海外托管与腾讯云 CloudBase 中国 Demo。

## Success Metrics

### 产品指标

- 首次研究完成率、报告生成成功率、平均完成时间。
- 审阅者修改轮次、模块级修订准确率、版本保留率。
- 证据可追溯率、引用有效率、关键模块非空率。
- 企业评分与行动计划的接受率、行动完成率和计划更新率。

### 质量指标

- 市场口径确认率和冲突发现率。
- 事实可核验率、推断解释率、预测假设覆盖率。
- 正式报告内部编码泄漏率为 0。
- 关键工作流端到端自动化测试通过率。

### 商业指标

- Demo 到试点转化率、付费试点数量、续约率、单位研究毛利率。
- 场景包复用率与新增行业/场景的交付周期。

## Open Questions

- 中国与海外生产环境最终采用统一数据平面还是区域化数据平面。
- 首个商业化场景优先 PE/VC 还是中小企业增长决策。
- 持续感知的抓取频率、来源授权和通知机制。
- Company Scorecard 的行业基准如何从案例库逐步校准。
- 正式 SaaS 的计费单位采用席位、项目、Token/搜索额度还是“软件 + 专家服务”。
