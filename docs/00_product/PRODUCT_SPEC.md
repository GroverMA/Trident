# Product Specification

## Product Overview

Trident 是一个证据优先、可审阅、可扩展的行业研究与企业战略决策 Agent。产品通过两种研究方式呈现同一套专业研究标准：

- **构建式研究**：从问题开始，用户参与关键节点确认。
- **审阅式研究**：确认范围后先生成初稿，用户从结论反向检查逻辑与证据。

企业战略决策支持在行业研究底座之上增加企业一手资料、Company Scorecard、Action Plan 和 Enterprise Report。

## Product Goals

1. 让非技术用户在一个工作台内完成研究、审核、修订与导出。
2. 让每个关键判断都能追溯到证据、假设和责任节点。
3. 根据原始 Prompt 动态调整研究重点和报告标题，不机械套模板。
4. 把行业洞察转换为企业定位、战略差距和可执行行动。
5. 保持模型、搜索、数据库、部署和场景模块可替换。
6. 保持海外与中国大陆两个部署目标功能同源、流程同源、版本同步；区域部署差异不得
   形成产品功能分叉。

## Functional Requirements

### FR-01 研究方式选择

- 页面使用“选择你的研究方式”，不得表述为权限或固定身份。
- 提供 Research Build First 与 Report Review First 两张同等视觉权重的卡片。
- 项目内可切换方式；不得清空项目内容、证据、人工修改或进度。

### FR-02 项目管理与记忆

- 创建、打开、继续、存档、终止、删除和分类项目。
- 显示进度、当前节点和更新时间。
- 打开历史项目应回到最近工作节点。
- 当前实现以项目快照保存；长期计划扩展为事件与时间化记忆。

### FR-03 Prompt Analysis 与 Research Brief

- 必填：行业、地区、研究目标/核心研究需求。
- 可选：目标公司、时间范围、企业战略意图、输出语言。
- AI 主动拆解关键问题、信息缺口和研究边界。
- 企业战略路径仅在用户启用后显示企业相关字段。

### FR-04 Gate 0 市场口径

- 生成市场定义、纳入范围、排除范围、相邻市场和待验证问题。
- 所有内容均可编辑。
- 待验证问题采用左右对应布局：左侧问题、右侧研究者确认口径。
- 用户确认后才进入后续研究。

### FR-05 研究计划与网页证据

- 将研究需求拆成覆盖完整 SOP 的任务与搜索式。
- 首轮搜索应尽可能充分；未覆盖问题在 Evidence Review 中呈现处理方案，不进入无限补检循环。
- 保存来源 URL、标题、时间、原文摘要、证据陈述、类型、相关性与质量信号。

### FR-06 Evidence Review

- 支持系统推荐、批量选择、全选与逐项查看。
- 用户确认文字必须显著标红、加粗并标注“必选”。
- 低覆盖内容允许带限制继续，但正式报告不得写“资料不足”或补充来源建议。
- 采用/拒绝/删除企业资料的状态必须一致并可追溯。

### FR-07 行业分析

- 至少覆盖行业定义、赛道与产业链、市场规模、竞争格局、驱动因素与关键条件。
- 竞争格局和驱动因素不得因单次模型字段缺失而输出空白。
- 结构化校验前应执行同义词归一化、容错映射和必要的安全回退。

### FR-08 Future Intelligence

- 基于驱动因素、制约因素、玩家布局、商业逻辑和客户需求生成趋势。
- 至少包括基准、加速和受阻情景、触发条件、反证条件和可观测指标。
- 有足够时间序列时可使用定量模型；否则明确采用因果情景法。
- 输出标题应响应 Prompt，例如“未来十年发展趋势”而不是固定模板名。

### FR-09 Enterprise Sensing

- 支持多批次、多数据层面的 DOCX、XLSX、PPTX、PDF、TXT、MD、CSV 文件。
- 单文件上限目标为 300 MB；部署平台仍需同步配置请求体与持久化限制。
- 记录数据层面、期间、来源角色、战略相关性、敏感级别和审核状态。
- 文件加入后清空上传表单，便于继续添加下一批资料。
- 自我诊断只保留“当前表现、症状或已观察到的问题”等不重复字段。

### FR-10 Company Scorecard

- 维度根据行业趋势与企业战略意图动态生成，建议 4–8 个。
- 每个维度包含公司得分、市场平均基准、战略目标要求、差距、权重、核心量化指标、置信度和判断依据。
- 雷达图同时显示三条曲线：公司、市场平均、战略目标。
- 市场基准是可比玩家平均能力，不是理想分；战略目标要求才是目标阈值。
- 即使数据不完整，也应基于已接受企业资料与行业研究形成带置信度的可解释估计，不得整块空白。

### FR-11 Action Plan

- 由 Company Scorecard 差距、行业趋势和战略目标共同驱动。
- 只分短期与长期，不机械切成任意时间段。
- 每项行动明确：做什么、责任人/角色、何时开始、衡量指标、依赖与风险。
- 优先级与组合风险使用清晰 bullet points。

### FR-12 报告审阅与版本

- 审阅范围支持完整报告或指定模块。
- 用户选择哪个模块，AI 只重生成该模块；未选择模块、Company Scorecard 和 Action Plan 必须原样保留。
- 支持多轮会话、建议、采纳、保存新版本和版本历史。
- 企业版审阅同样适用。

### FR-13 报告与导出

- 网页、Word、PDF 使用同一内容模型和样式设置。
- 支持字体、标题层级、颜色、字号、行距与段距配置。
- 层级编号连续，例如 1、1.1、1.1.1。
- 不允许内部 ID、Emoji、工程错误、乱码或标点出现在段首。
- 引用链接必须指向对应来源；来源放在脚注/附录，不在正文用“根据某机构”替代分析。

## Non-functional Requirements

- **可靠性**：长任务可重试、可恢复，局部失败不清空既有成果。
- **性能**：页面操作即时反馈；长任务异步化后提供进度和阶段状态。
- **可扩展性**：场景包、行业包、算法策略和评估器使用明确契约。
- **安全性**：凭证仅通过服务端环境变量；企业资料默认私有。
- **可观测性**：记录任务状态、错误类型、模型/搜索调用和成本，但不记录敏感正文。
- **兼容性**：中国与海外部署共用代码；供应商适配器可替换。
- **双区域一致性**：研究流程、功能、API、领域模型、Skill 和报告标准在 Vercel 与
  CloudBase 间保持一致；区域差异只存在于基础设施和配置层。
- **可访问性**：关键控件对比度、字号和状态提示满足基本可访问性要求。

## User Stories

- 作为研究员，我希望逐步确认市场口径和证据，以控制研究质量。
- 作为审阅者，我希望先看到完整报告，再按模块提出问题并保留其他内容。
- 作为企业管理者，我希望上传经营资料后看到自身位置、目标差距和行动建议。
- 作为投资经理，我希望将行业证据、标的画像和投委会判断串联起来。
- 作为管理员，我希望知道谁在何时修改了什么，并能控制数据访问。

## Acceptance Criteria

1. 两条研究方式均能从创建项目运行到可下载报告。
2. 切换研究方式后数据和进度不丢失。
3. 六个通用研究模块均有非空、与 Prompt 相关的内容。
4. 模块级审阅只修改选中模块，未选内容字节级或语义级保持不变。
5. 企业路径生成非空 Scorecard、雷达图和短/长期 Action Plan。
6. Word/PDF 与网页报告层级和标点规范一致。
7. 正式报告中搜索不到 `EVD-`、`FND-`、内部字段名或敏感凭证。
8. API/模型故障给出可恢复状态，不向终端用户暴露堆栈。
9. 每项迁移、新功能与修复均通过同一测试集，并在海外与大陆部署目标完成发布验收；
   任一区域未通过时不得宣称双区域版本完成。

## Edge Cases

- 搜索结果重复、付费墙、过期链接或来源冲突。
- 模型返回 JSON 外文本、同义字段、空列表、非法枚举或未知证据 ID。
- 文件过大、解析超时、无文字层 PDF、乱码表格或宏文件。
- 用户中途切换路径、返回前一节点或修改已确认口径。
- 企业资料被拒绝或删除后仍被下游缓存引用。
- 部署没有 `DATABASE_URL` 时，中国 Demo 显式使用 SQLite；生产环境不得静默回退。

## Permissions

### 当前

- Demo 以单用户/单环境体验为主，不承载正式权限承诺。

### 规划

- 组织、项目和资料级 RBAC。
- PostgreSQL RLS、多租户隔离、审计日志。
- 管理层、研究负责人、投资经理、贡献者和只读审阅者角色。
- 企业 SSO 与密钥管理。

## Data Requirements

- 项目、简报、计划、证据、分析、趋势、企业资料、评分、行动、报告版本与事件。
- 所有对象具有稳定 ID、所属项目/租户、创建者、时间戳、版本和状态。
- 证据与结论保留引用关系；正式报告渲染层隐藏内部 ID。
- 企业文件正文与元数据分离，敏感级别影响检索与模型上下文。

## Analytics

- 项目漏斗：创建→口径确认→证据确认→分析→报告。
- 任务耗时、重试、失败阶段与恢复率。
- 证据采纳率、来源多样性、引用有效率。
- 审阅轮次、模块修改范围与用户接受率。
- Scorecard 差距、行动完成率和后续调整。
- 模型 Token、搜索、文档解析与存储成本。

## Future Extensions

- Profile Engine、Simulation Engine、Adaptive Planning Engine。
- PE/VC 投资研究、投后监测与投委会模拟。
- 中小企业增长策略订阅与持续经营建议。
- 外部新闻政策 + 内部经营信号的持续感知。
- 时间化长期记忆、企业知识图谱与算法策略市场。
