# User Journey

## Journey Overview

Trident 提供三条共享底层数据的主要旅程：构建式通用研究、审阅式通用研究、企业战略研究。两种研究方式是进入路径，不是权限身份。

## Journey A：构建式研究（Research Build First）

### Entry Point

用户在“选择你的研究方式”中选择“从问题开始”，或在项目内切换为构建式研究。

### Steps

1. 输入项目名称、行业、地区与核心研究目标。
2. AI 分析 Prompt，生成 Research Brief 与关键问题。
3. 用户编辑并确认 Gate 0 市场定义与待验证口径。
4. AI 生成研究计划并执行网页证据检索。
5. 用户在 Gate 1 批量审核证据和处理未覆盖问题。
6. AI 生成行业分析与未来趋势。
7. 用户在内容确认节点查看、编辑或返回前一节点。
8. 系统生成正式报告并提供网页、Word 与 PDF。

### Decisions

- 是否启用企业战略决策支持。
- 是否接受市场定义与搜索覆盖。
- 哪些证据进入分析。
- 是否返回上一节点修改，或进入报告。

### Friction

- 搜索耗时、证据数量过多、市场口径含糊、模型结构化输出失败。

### Expectations

- 每一步目的明确、进度可见、错误可恢复。
- 第一次搜索足够完整，不被无限补检阻塞。

### System Response

- 保存每个节点产物和状态。
- 对模型字段执行归一化与校验；失败时保留已有成果并重试当前阶段。
- 未覆盖问题提供研究处理方式，不写入正式报告。

### Success State

生成结构完整、引用可追溯、可下载的行业报告。

### Failure State

某阶段失败时显示可操作的恢复按钮与简明原因；不得暴露堆栈，不得要求从头重做。

## Journey B：审阅式研究（Report Review First）

### Entry Point

用户选择“生成报告初稿”。

### Steps

1. 输入同样的研究需求。
2. AI 生成 Prompt Analysis 与 Gate 0 市场口径。
3. 用户确认范围。
4. 后台一次完成搜索、证据整理、行业分析、趋势预测与报告组装。
5. 用户先查看完整报告。
6. 用户通过 Content Revision 选择要修改的模块并提出问题。
7. AI 解释、建议，用户确认后生成新版本；未选模块保持不变。
8. 用户进入 Reference Check、Industry Analysis、Future Intelligence 等页追溯方法。
9. 反复修订直至确认并导出。

### Decisions

- 选择审阅范围、接受/拒绝建议、是否保存为新版本、是否完成审阅。

### Friction

- AI 可能误把局部修改理解为重写全文。
- 报告先生成会产生等待时间。

### Expectations

- 先看到完整结论；模块修订具有局部性、可回滚和版本记录。

### System Response

- 对每次修订建立模块快照和变更集。
- 组装新版本时使用未变模块的原始快照，而不是重新生成。

### Success State

审阅者确认报告版本，所有修改、疑问和引用可追溯。

### Failure State

修订失败只影响当前草稿，稳定版本保持不变。

## Journey C：企业战略研究

### Entry Point

用户在首页启用“企业战略决策支持”，并填写目标企业与战略意图。

### Steps

1. 进入 Enterprise Sensing 前置节点。
2. 完成企业自我诊断和 AI 主动访谈。
3. 分批上传不同数据层面的企业文件，标注来源、期间、战略关系和敏感级别。
4. 人工接受、拒绝或删除资料，确认数据权限。
5. 按构建式或审阅式路径完成行业研究。
6. 系统从行业趋势与企业战略意图生成评分维度和量化指标。
7. 生成 Company Scorecard：公司得分、市场平均、战略目标与差距雷达图。
8. 从关键差距生成短期、长期 Action Plan，明确做什么、谁做、何时开始。
9. 形成 Enterprise Report 并支持模块化审阅。

### Decisions

- 哪些企业资料可进入模型、哪些只能内部保存。
- 战略意图与优先目标是否准确。
- 哪些评分差距是行动重点。

### Friction

- 文件大、格式复杂、数据口径不一致、企业陈述与事实混淆。

### Expectations

- 建议与企业真实能力相关，而不是通用咨询模板。
- 所有内部资料默认私有，审阅状态一致。

### System Response

- 资料按层面和敏感级别切分；只将允许内容送入模型。
- 评分给出核心指标与置信度；数据不足时做可解释估计，而非空白。

### Success State

管理层获得企业市场位置、战略目标差距和可执行行动组合。

### Failure State

单个文件解析失败不阻塞其他资料；评分或行动阶段失败可独立重试。

## Journey D：持续决策循环（规划）

1. 持续抓取政策、新闻、竞争者、客户和内部经营指标。
2. 新信号与项目、企业画像、战略假设建立关联。
3. 超过阈值时触发通知、重新评分或情景模拟。
4. 管理者通过对话更新执行进度。
5. Adaptive Planning Engine 调整 Action Plan 并保留变更原因。
